# 대신봐드림 - 롱폼 CC 영상 리뷰 쇼츠 루틴

## 컨셉 (두 가지를 같이 운영)
크리에이티브 커먼즈(CC BY) 롱폼 영상을 쇼츠로. 젊은 세대가 좋아하는 건 다 다룬다:
K-POP·POP·JPOP, 요즘 핫한 걸그룹, 직캠, 콘서트, 연예계·연예인 활동, 룩북, 브이로그, 외국 이야기,
반려동물(강아지·고양이 귀여운 영상), 로블록스, 생활꿀팁, 예능·코미디(코빅·1박2일 같은 개그 프로그램). (치이카와·치어리더 제외)
- 직캠·콘서트: 노래가 깔린 무대 구간은 음원 신고 대상이라 쓰지 않는다. 멘트·팬 소통·리액션·실수·비하인드 순간만
- 룩북: 선정적인 장면·각도는 쓰지 않는다 (유튜브 정책). 코디·분위기·반응 위주
- 반려동물: 하루한픽(B)에 잘 맞음. 귀여운 행동·반전 순간
- **A. 리뷰** (40~55초): 처음 TTS 훅 → 원본 장면들(출연자 목소리) → 마지막 TTS 마무리
- **B. 하루한픽** (15~30초, TTS 없음): 하이라이트 장면을 먼저 살짝 → 그 장면까지의 흐름 → 펀치라인.
  흰 화면 위 영상 + 상단 제목 + 하단 한 줄 코멘트 + 출처. 세로(폰 촬영) 원본이면 자동으로 전체 화면 + 상단 흰 제목 띠 + 초록 코멘트. 웃긴 순간·리액션·반전이 있는 원본(특히 예능)에 맞음
- **C. 꿀템 추천** (20~30초, 참고: 소개팁 "삶의 질 떡상하는 아이디어템"): 제품 4~5개를 4~6초씩 빠르게 이어 붙인 리스트형.
  script 에 `"shop": true` (마지막에 "추천템은 프로필 링크에서!" 표시. 다른 컨셉에는 넣지 않는다).
  각 장면 = 제품이 실제로 쓰이는 원본 장면 + `"label": "눈 세척컵"` (빨간 박스 키워드, 6자 안팎). 나레이션은 없거나 첫 장면 훅 한 줄만.
  제목: "삶의 질 *떡상*하는\n아이디어템 5" 처럼 숫자+혜택. 여러 꿀템 원본에서 장면을 모아도 됨(source 는 장면마다 같아야 하므로 원본 하나 안에서 4~5개를 고른다)
  쿠팡에서 살 수 있는 일반 제품만. 의약품·건강기능식품·성인용품·위험물은 하지 않는다. 효능을 지어내지 않는다(원본이 말한 것만)
- **D. 이슈 썰** (30~45초, 참고: 따봉햄찌 "~한 이유", "~의 최후"): 원본 영상 없이 만드는 이야기 쇼츠. TTS 나레이션 전체 + 대사 자막.
  `"style": "story"` (검은 화면, 상단 제목, 가운데 사진, 아래 자막, 배경음악 아주 작게 - 쇼츠BGM 폴더에서 자동).
  사진은 `python3 shorts/source.py images "<검색어>"` 로 찾은 것만 (Pixabay + 위키미디어 공용, 재사용 가능한 라이선스만 나옴).
  장면마다 `"img": [URL, URL]` 처럼 2~3장 넣어 빠르게 넘긴다. 내용과 맞는지 URL 을 받아 직접 보고 고른다. Pixabay 영상(`query`)도 가능
  위키미디어 사진을 쓰면 설명란에 "🖼 사진: <저작자> / Wikimedia Commons / <라이선스>" 를 적는다 (Pixabay 는 표기 불필요)
  구글 이미지 검색·뉴스 사진·남의 영상 캡처는 쓰지 않는다 (라이선스 확인이 안 됨)
  주제: 기업·브랜드 흥망, 신기한 역사·과학, 세계의 기막힌 사건, 물건의 숨은 이야기. 웹 검색으로 **믿을 만한 출처 2곳 이상**에서 확인한 사실만
  금지: 실존 인물(특히 일반인) 비방·범죄 단정, 진행 중인 재판 결론, 사망·사고 희화화, 의학·투자 조언, 확인 안 된 소문. 남의 영상 대본 베끼기 금지(재사용 콘텐츠로 수익 정지 위험)
  구성: 훅(결과·반전 먼저) → 배경 → 전개 → 반전 → 질문으로 마무리. 나레이션 250~350자, 해요체.
  장면은 문장 끝에서만 나누고 "..." 는 쓰지 않는다. 숫자는 읽기 쉽게("2001년", "130억 달러")
  설명란에 "📚 참고: <출처 기사·문서 제목 - 매체>" 를 적는다 (원본 youtu.be 링크 대신)
- **E. 라이브 클립** (참고: 음소개 "원곡자 앞에서 ~ 불러버린 OOO", 구독자 모으기용): 노래 부르는 구간을 원본 소리 그대로, **편집 없이 한 구간**.
  `"style": "pick"` 레이아웃, `orig` 장면 1개, TTS 없음. 곡의 **훅(후렴·고음·화음이 터지는 부분)이 잘 들리게** 시작·끝을 잡는다.
  길이는 훅이 다 들어가는 만큼 (보통 30초~2분), **3분 미만 필수**. 중간을 자르거나 이어 붙이지 않는다
  title = "원곡자 앞에서 *레전드* 찍은 OOO" 처럼 상황+감탄 한 줄, comment = 듣는 사람 반응 한 줄("첫 소절부터 소름…")
  원본은 **CC 라이선스 + 가수·소속사·방송사 공식 채널** 것만 (재업로드·팬캠 편집본 금지). 가사 자막은 넣지 않는다
  ⚠️ 채널 주인이 알고 선택한 위험: 노래는 곡 저작권자가 신고(Content ID)할 수 있다 (1분 넘으면 신고 시 차단될 수 있음, 감수). **실행당 최대 1개**.
  업로드 후 저작권 신고·차단 알림이 오면 보고에 적고, 같은 곡·같은 원본은 다시 쓰지 않는다. 저작권 '경고(strike)'가 생기면 E 를 멈추고 보고
  설명란: 감성 소개 2~3줄 + "원곡: <가수 - 곡명>" + "보컬: <가수>" + 원본 youtu.be 링크·CC BY + 해시태그(#라이브 #귀호강 #레전드라이브 등)
- 한 번 실행에 3개: **A 1개 + B 1개 + D 1개**. CC 라이브 원본이 있으면 B 대신 E 1개. 꿀템 원본이 있으면 A를 C로. B에 맞는 장면이 없으면 A로. 원본이 없으면 D만 3개
- 배경음악 없음 (두 컨셉 모두)
- 방송사 예능(1박2일·코빅 등)은 대부분 CC가 아님 → 저작권자가 직접 CC로 올린 것만 사용

## 구성
- 계정: 채널 계정 (채널명 대신봐드림), 환경 변수 YT_* / GOOGLE_TTS_KEY (브랜드 채널이면 DRIVE_REFRESH_TOKEN)
- 원본: 사용자가 채널 계정 드라이브 `롱폼원본` 폴더에 넣음. 파일명에 `[유튜브ID]` 권장 (예: `세븐틴 브이로그 [md5zNFKvfvE].mp4`).
  [유튜브ID]가 없으면 파일명(=영상 제목)으로 CC 영상을 찾아 매칭. 같은 이름의 .srt/.vtt 가 있으면 자막으로 씀. 없으면 faster-whisper 로 자동 생성 (`*.hf.co` 네트워크 허용 필요)
- 클라우드에서 YouTube 직접 다운로드는 봇 차단으로 불가 → 드라이브 경유
- `source.py` 원본 목록/가져오기 → `make.py` 쇼츠 생성 (원본 구간 + 원본 목소리 + 상단 제목, A는 처음·끝 TTS. 대사·나레이션 자막은 넣지 않음) → `upload.py` 예약 공개
- 브랜딩: `channel/brand.py` (프로필, 배너. `shorts/intro.mp4` 는 만들어 두기만 하고 쇼츠에는 안 씀)
- 루틴: 06:40, 11:40, 17:40 KST에 제작 → 만들어지는 대로 바로 공개 (--privacy public)
- 주간 원본 추천 루틴: 매주 월요일, 받을 CC 영상 목록을 알림으로 보냄

## 루틴 한 번 = 이렇게
0. `pip install -q faster-whisper` (자막 없는 원본용)
1. `python3 shorts/source.py list` → `n/3 made` 인 원본 중 하나 고름 (`done`·`skip` 제외). 원본 하나로 서로 다른 장면 쇼츠 최대 3개.
   쓸 원본이 없으면 만들지 말고 "롱폼원본에 새 영상 필요"라고 보고하고 끝낸다.
2. `python3 shorts/source.py fetch <drive_id> src/` → `src/meta.json`, `src/transcript.txt`(초 단위 시작시각 + 대사), `src/frames.jpg`(타임스탬프 24장)
   - **license 가 creativeCommon 이 아니면 그 원본은 쓰지 않는다.**
   - 업로더가 실제 저작권자인지 확인: 공식 소속사·방송사·본인 채널 OK. 영화·드라마·음방을 개인이 CC로 재업로드한 건 쓰지 않는다
   - `upload.py --recent` 에 같은 원본 ID로 이미 만든 쇼츠 제목이 있으면 그것과 다른 장면·다른 포인트로 쓴다
3. transcript.txt 와 frames.jpg(필요하면 해당 구간 프레임을 ffmpeg로 더 뽑아 직접 봄)를 보고 script.json 작성.
   **B. 하루한픽** script:
   ```json
   {"style": "pick", "title": "황제성이 무대에 *난입*한 이유", "comment": "화난 황제성이 제일 웃김ㅋㅋ",
    "credit": "출처 <원본 채널명>", "source": "src/video.mp4",
    "scenes": [{"orig": [하이라이트 시작, 끝], "lines": [...]}, {"orig": [...], "lines": [...]}]}
   ```
   - 첫 장면 = 펀치라인을 2~3초만 미리 보여줌(궁금증). 그다음 그 장면에 이르는 흐름을 원본 그대로 이어서 끝까지
   - say 금지(TTS 없음). 제목은 "~한 이유", "~의 결과" 처럼 궁금하게 20자 이내, 강조 *단어*는 분홍
   - comment 는 시청자 같은 한 줄 반응 (ㅋㅋ 허용), 15자 안팎
   - 합계 15~30초. 노래·무대 음악 구간 금지는 똑같이

   **A. 리뷰** script:
   ```json
   {"title": "상단 고정 제목 2줄, *강조*는 노란색", "source": "src/video.mp4",
    "scenes": [{"say": "훅", "src": [시작초]}, {"orig": ...}, {"orig": ...}, {"say": "마무리", "src": [시작초]}]}
   ```
   - 나레이션(say)은 **첫 장면과 마지막 장면에만** (make.py가 다른 위치면 거부). 가운데는 전부 원본 장면
     · 나레이션 장면 `{"say": "...", "src": [시작초, ...]}` : 리뷰어 목소리(TTS) + 원본 화면(소리 없음)
     · **원본 장면** `{"orig": [시작초, 끝초], "lines": [[시작초, "이름", "대사"], ...]}` : 출연자 목소리 그대로. 3~15초 (lines 는 장면을 고르는 메모용, 화면에 자막으로 나오지 않음)
       시작초·대사는 transcript.txt 에서 그대로. 이름은 **성 빼고 두 글자**(도겸, 승관, 민규)로 분홍색 표시.
       이름은 원본 자막·대화 문맥(예: "[사진을 찍는 민규]", 본인 호칭)으로 **확실할 때만**. 애매하면 "" (얼굴로 판단하지 않는다)
   - 구성(40~55초): 훅 나레이션(영상 요약, 흥미를 끄는 말) → 원본 장면 3~4개 → 마무리 나레이션 + 질문.
     **원본 장면 3개 이상** — 재미는 출연자 본인 목소리에서 나온다. 웃긴 말·반전·리액션 순간을 transcript에서 고른다
   - 원본 장면에 노래·무대 음악이 깔린 구간은 쓰지 않는다 (음원 신고). 예외: E 라이브 클립. 말소리 구간만
   - 나레이션은 줄거리 요약 금지. **리액션하는 친구 말투**: 짧게 끊고, 감탄·질문·반전을 넣는다
     좋음: "근데 여기서 반전이에요." / "아니 이걸 본인이 말한다고요?" / "이 표정 좀 보세요."
     나쁨: "~했어요. ~했어요." 식 나열, "~할 정도였어요", 설명문
   - 나레이션 장면은 **문장이 끝나는 곳에서만** 나눈다 (한 문장을 두 장면에 걸치면 중간에 끊겨 들림). "..." 쓰지 않기
   - 해요체 유지(반말·은어 금지)지만 문장마다 감정이 있어야 함. 한 문장 25자 이내 권장
   - 첫 2초 훅: 결과/반전/질문을 먼저 ("민규가 갑자기 대기실에 나타난 이유, 아세요?")
   - 마지막: 시청자에게 질문 하나 ("여러분은 누구 편이에요?") — 댓글 유도
   - 나레이션 합계 150자 안팎 (상한 700자)
4. `python3 shorts/make.py script.json -o short.mp4`
5. 제목(40자 이내, 인물·숫자·구체어)과 설명란 → `python3 shorts/upload.py short.mp4 --title ... --desc ... --privacy public`
   설명란 형식 (해시태그 3개 미만이면 거부, `youtu.be/ID` 링크로 원본 사용 횟수를 셈 - 반드시 넣을 것):
   ```
   한 줄 요약 (이 영상에서 뭘 볼 수 있는지)

   ✅ 포인트 1
   ✅ 포인트 2
   ✅ 포인트 3

   📺 원본: <원본 제목> - <채널명>
   https://youtu.be/<유튜브ID>
   라이선스: 크리에이티브 커먼즈 저작자 표시(CC BY)

   #대신봐드림 #<인물/그룹> #<분야> ... 8~12개 #shorts
   ```
   쿠팡 문구("이 포스팅은 쿠팡 파트너스 활동의 일환으로…")는 C 꿀템처럼 쿠팡·추천템을 언급할 때만 upload.py 가 자동으로 붙인다
   B 는 제목 앞에 "하루한픽 | " 을 붙이고 해시태그에 #하루한픽 추가
   C 는 해시태그에 #생활꿀템 #쿠팡꿀템 #아이디어템 #자취꿀템 추가, 설명란은 제품마다 이모지 블록 (위의 한 줄 요약·✅ 포인트 대신):
   ```
   🛒 제품은 채널 프로필 '쿠팡 추천템' 링크 → 쿠팡에서 검색

   👍 <제품명> (쿠팡 검색어: "<검색어>")
   <언제 좋은지 + 원본이 말한 장점 1~2줄, 해요체>

   🎵 <제품명> ... (제품 수만큼, 이모지는 제품에 맞게)
   ```
   (쇼츠 설명란 링크는 유튜브가 클릭을 막아 두어서 제품 링크 대신 프로필 링크로 안내한다)

## 말 끊김 금지 (모든 컨셉)
- 원본 장면(`orig`)은 transcript.txt 의 줄 시작 시각에서 시작하고, 말하던 문장이 끝난 뒤(다음 줄 시작 시각)에서 끝낸다
- make.py 가 원본 폴더의 transcript.txt 를 보고 장면을 문장 단위로 자동으로 넓힌다 (중간에 잘리지 않게). 그래서 장면이 생각보다 조금 길어질 수 있으니 총 길이를 확인한다
- 나레이션(TTS)은 문장 끝에서만 장면을 나누고 "..." 를 쓰지 않는다

## 중복 금지
- 만들기 전에 `python3 shorts/upload.py --recent` (채널 전체 제목)를 보고 **같은 원본의 같은 장면, 같은 주제(D)** 는 만들지 않는다
- upload.py 가 비슷한 제목을 찾으면 업로드를 거부한다. 정말 다른 장면·이야기일 때만 `--not-duplicate`
- 원본당 최대 3개 (`source.py list` 의 n/3 이 채널 전체 기준)

## 쿠팡 파트너스 주의사항
- 링크를 홍보하는 모든 곳(영상 설명란·채널 설명)에 위 문구를 그대로 넣는다 (공정위 심사지침)
- 메신저·SNS·댓글로 링크를 뿌리지 않는다 (불법 스팸 처벌 대상). 링크는 채널 프로필에만 둔다
